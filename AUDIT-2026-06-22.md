# Nodea full audit — 2026-06-22

Method: a 15-lane multi-agent audit (one auditor per subsystem, every finding
adversarially re-verified against the real code). 11 of 15 lanes completed before
a session limit cut the run short; the remaining 4 (**tree-canvas,
persistence-rls, chat-projects, config-misc**) were never audited and should be
re-run.

Headline: the core happy-path chat pipeline is **not** broken by a wrong model id
or a malformed request — those were ruled out. The real damage was concentrated
in **concurrency, an over-tight input cap, error-handling dead-ends, and billing
downgrade gaps**. 16 fixes applied (below). Larger items are proposed, not
touched.

## 🏗 Propose, don't fix (need a decision / architecture)

### A. Collab — members can't create or file chats into a shared Project  **(High, broken feature)**
`src/app/api/conversations/[id]/project/route.ts` requires the target project to
be **owned by the caller**. A member who starts a new chat inside a shared
project can't file it there — it becomes an orphan the team never sees, breaking
the core "shared team space" promise.
**Proposed:** change the assign check from "owner" to "owner OR accepted member
of the `chat_project`"; confirm RLS on `conversations`/`nodes` grants member
read. Separately, `/api/chat` meters the sender but does **not** verify they may
post to a shared `conversationId` — add a membership check. Touches the
membership model + RLS, so worth doing deliberately.

### B. Mobile — attachments entirely non-functional  **(Med–High parity gap)**
The mobile composer's attach button is a decorative no-op (no handler, no file
input), and messages with attachments render text-only.
**Proposed:** wire the attach button to a hidden `<input type="file">` feeding
the same `pendingAttachments` → `/api/upload-attachment` pipeline desktop uses;
render attachment chips/images in the mobile message view. Also add a Next
`viewport` export with `viewport-fit=cover` so the existing `env(safe-area-*)`
CSS actually applies on notched devices.

### C. Auth — no `middleware.ts` for Supabase SSR session refresh  **(robustness/security)**
There is no middleware, so the documented Supabase SSR cookie-refresh per
navigation is absent; server route handlers and parallel tabs can act on
stale/expired sessions.
**Proposed:** add `src/middleware.ts` using `@supabase/ssr`'s `updateSession`
pattern with a matcher excluding static assets. ⚠️ Read `AGENTS.md` / the Next 16
docs in `node_modules/next/dist/docs/` first — this Next has breaking changes.
Cross-cutting, so don't add blind.

### D. Demo — no durable server-side spend/abuse cap  **(cost/abuse)**
The 5-message limit and half-cent cap are client-side only; the lone server
backstop is an in-memory per-instance IP rate limit that resets on cold start and
doesn't coordinate across Vercel instances. A scripted caller can pull unbounded
(individually cheap) Haiku completions.
**Proposed:** move the cap to a shared store (a Supabase table or Vercel KV)
keyed by IP+day, enforced in `/api/demo/chat`. Also: the char-budget trim there
can drop the leading user turn and send an assistant-first array → Anthropic 400;
guard to always keep a leading user message.

### E. Memory — auto-extraction fires an uncapped Haiku call every Pro turn  **(cost)**
Every Pro message triggers `/api/memory/extract` (a Haiku `generateText`).
**Proposed:** gate it — only every N turns, or only on fact-bearing messages, or
skip when already at the 30-memory cap.

## 🔍 Found, not yet fixed (smaller; quick wins, lower priority)

- **Auth:** "Keep me signed in" checkbox is inert (`remember` state never read) — implement session-vs-local persistence in the supabase client factory, or remove the checkbox (currently mildly deceptive).
- **Auth:** password min-length inconsistent — signup requires 8, `/login/update-password` allows 6. Align to 8.
- **Auth:** login metadata advertises "anonymous sign-in" that doesn't exist in code — fix the copy.
- **Memory:** chat context loads the **oldest** 30 memories (`loadUserMemories` orders ascending) — should load newest for injection.
- **Memory:** in-chat "saved to memory" badge is session-only (vanishes on reload); `MAX_MEMORY_*` constants duplicated between `memory.ts` and `SettingsModal.tsx` and can drift.
- **Admin:** the three `/api/track*` endpoints share one rate-limit bucket key — heavy event traffic can starve pageview/duration tracking. Use per-endpoint keys.
- **Chat:** `recordTokenUsage` overage warning always compares to FREE limits regardless of plan (misleading logs only).
- **Models:** Opus pinned to `claude-opus-4-7` — valid/active, but one generation behind `claude-opus-4-8`. Optional bump.
